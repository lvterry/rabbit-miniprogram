| 顺序 | 工作 | 验收标准 | 状态 |
| --- | --- | --- | --- |
| 1 | 学员详情、编辑、充值、预约统一使用云端 | 不再根据本地 ID 切换数据源；失败可重试 | 已完成 |
| 2 | 首页与课次详情读取真实预约 | 新预约出现在首页，可进入课次详情 | 已完成 |

| 4 | 收入报表接入收款数据 | 添加课时填写的费用产生收款；按收款时间和课程汇总 | 已完成 |

- 现有云托管环境：`prod-d8gfpc80m60219d51`，服务：`express-2wy2`。
- 服务通过 GitHub 的 `main` 分支自动构建部署；本地 `main` 与 `origin/main` 均为 `6939647`。当前云端账号接口已返回该提交引入的 `loggedIn` 字段；构建上下文为 `server/`，端口 80。
- 使用服务已有的 MySQL 连接配置和建表权限；密码继续仅存于云托管环境变量。
- 保留已有云端课程、学员、充值和预约。旧本地演示数据不自动上传。
- 学员邀请认领、多课程选课、课时有效期、退款流程属于业务模型中的后续功能，现有页面没有这些流程，不在本次 mock 替换中扩展。

## 上线验收

1. 确认自动构建的仓库/分支为本项目待发布代码，应用目录与构建上下文为 `server/`；上传体验版时在微信开发者工具中填写版本号 `0.1.0`。
2. 确认云托管构建和数据库初始化成功；旧业务数据已完成迁移，避免将服务切回只读写旧预约表的版本。
3. 确认健康检查、首页、学员列表、「我的课程」和财务报表正常读取；「我的」页面当前只显示菜单，账号入口暂时隐藏。
4. 创建课程与学员（或使用自己指定的测试档案），添加课时及实收金额，检查学员余额、记录和报表。
5. 添加预约，确认首页及学员详情均可进入同一课次；改期、备注、取消扣次/不扣次、恢复、完成和撤销均有历史。
6. 验证余额不足会阻止扣次，切换微信用户无法读取他人的资料，重新编译后数据仍在。
7. 提交反馈并确认保存；用真机走完整操作链路。手机号授权入口仍隐藏，不属于本次体验版验收范围。
