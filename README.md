# 小兔排课 · 交互原型

微信小程序原生代码制作的交互原型。课程创建和「我的课程」列表已接入云托管；学员、收入、反馈和演示账号状态仍使用本地模拟数据。

## 打开

用微信开发者工具打开本目录即可。项目配置已包含小程序 AppID。打开后编译首页，在「今日」里点选课程体验课程详情与操作。

## 可体验的流程

- 今日课程及近期课程 → 课程详情
- 改期、编辑课程备注
- 取消课程（消耗或不消耗课时）、恢复课程
- 标记完成、撤销完成
- 操作历史与状态变化
- 学员活跃/未活跃列表与学员详情
- 编辑学员资料、添加课时与查看记录
- 为学员添加预约，预约会出现在首页课程列表
- 「我的」页面的访客与演示账号状态
- 我的课程：编辑、新增课程，查看课程学员名单并进入学员详情
- 财务报表：总收入、按课程占比和按月份收入
- 关于页面与意见反馈
- 课程海报预览和小程序转发

除云端课程外，变更保存在微信开发者工具的本地存储中。「进入演示账号」只切换本地演示状态，不影响云端课程访问；转发使用小程序原生转发卡片。需要重置本地数据时可清除开发者工具中的本地存储并重新编译。当前数据和状态处理仅用于确认交互流程，不代表最终的数据结构或接口协议。

## Cloud Run 后端

`server/` 是独立的 Express 服务，提供 `GET /health` 健康检查。进入该目录运行 `npm ci` 和 `npm start` 即可启动；默认监听 80 端口，也可通过 `PORT` 指定端口。

部署到微信云托管时，使用 `server/Dockerfile` 构建，并部署到现有服务 `express-2wy2`。如果控制台支持选择子目录，请将应用目录或构建上下文设为 `server/`，Dockerfile 设为该目录下的 `Dockerfile`。容器服务端口设为 80。部署完成后，在微信开发者工具控制台手动运行 `getApp().testCloudConnection()` 检查连接；小程序不会在启动时自动请求健康检查。

### 课程创建接口（本地验证阶段）

`POST /courses` 接收课程名称 `name`（必填，最多 40 字）和介绍 `description`（可选，最多 500 字），成功时返回 201 和新课程。`GET /courses` 返回当前微信用户的课程列表。小程序通过 `wx.cloud.callContainer()` 调用时，无需点击演示账号入口；服务端从微信云托管转发的 `X-WX-OPENID` 读取用户身份，按用户隔离课程，不接受客户端提交的用户 ID。两个接口都要求 `X-WX-SOURCE`，无需配置 `TEACHER_OPENID`。

本地可用测试身份模拟微信请求：

```sh
cd server
npm ci
PORT=8080 npm start
```

```sh
curl -i -X POST http://127.0.0.1:8080/courses \
  -H 'Content-Type: application/json' \
  -H 'X-WX-SOURCE: local-test' \
  -H 'X-WX-OPENID: local-user' \
  -d '{"name":"西语入门","description":"初级课程"}'
curl -i http://127.0.0.1:8080/courses \
  -H 'X-WX-SOURCE: local-test' -H 'X-WX-OPENID: local-user'
```

目前课程数据仅保存在服务进程的内存中，重启或扩容后会丢失。小程序的「添加课程」会提交到云端，「我的课程」只显示云端课程；其他页面仍使用本地模拟数据。云端课程目前不可编辑。不要将此版本用于保存正式课程数据。
